## Project Summary

Ora is an AI-powered comprehension-check web app for UW CS courses: an instructor uploads an assignment, rubric, and guiding questions; a student submits code and is interviewed by an LLM (Claude Sonnet 3.5) in a text chat; the transcript is then summarized into a per-student report with a suggested score for the TA/professor to review. Tech stack is Next.js 16 (App Router, TypeScript), Tailwind, Supabase (Postgres + Auth + RLS), Anthropic Claude API for the interview and report generation, and ElevenLabs `scribe_v2` for optional voice-note transcription. Three contributors per `git shortlog`: Joel Varghese (28 commits, foundation + auth + professor flows), Garv Maheshwari (3 commits, student chat UI), Neil Chaudhari (1 commit, ElevenLabs voice transcription).

## Suggested Improvements & New Features

### Code Quality & Technical
- **Deploy to Vercel today.** This is single-handedly the highest-leverage thing you can do. Next.js + Supabase + env vars takes 15 minutes on Vercel's free tier. Add the live URL to the top of `README.md` and `PROPOSAL.md`.
- **Merge `joel-polish-pass` into `main`** (or cherry-pick `eda5856`, `03adb63`, `cbc8f57`, `c4662f4`). Your real landing page and password reset flow are not visible to the grader right now.
- **Fix the landing-page redirect.** `src/proxy.ts:54-57` unconditionally redirects `/` to `/login` for logged-out users, which means even after merging the rewritten landing page, no one will see it. Either remove that branch or only redirect when the user is authenticated.
- **Add `.next-dev*.log` and `.next/` to `.gitignore`** and remove the committed log files. The committed log even leaks a contributor's local path `C:\\Users\\neilc\\Spring2026\\IntroToAi\\Ora\\Ora`.
- **Delete `Github_Rules.txt`.** A checked-in instruction to strip AI co-authorship is an integrity smell on an AI-themed course assignment. Be transparent about AI assistance in your final write-up.
- **Use Claude's native multi-turn `messages` array** in `src/app/api/chat/route.ts:127-146` instead of flattening the transcript into one synthetic user turn. This unlocks prompt caching on the assignment/rubric system content and reduces token cost per turn substantially.
- **Validate the report JSON with Zod** in `src/lib/reports.ts:52-82` instead of manual `typeof` checks. You'll get clearer errors when the model hallucinates a field.
- **Add a few tests.** Unit-test the `parseGeneratedReport` JSON parser with malformed inputs; integration-test the RLS policies (Supabase has a SQL test harness). Even 5 tests would meaningfully strengthen the "well-structured, documented" rubric line.
- **Pin the Anthropic model** to a dated version like `claude-sonnet-4-5-20251001` instead of `claude-3-5-sonnet-latest`; "latest" can drift mid-semester and silently change grading behavior.

### UI / UX Improvements
- **Show the suggested rubric breakdown inline in the student-facing completion screen** (anonymized if needed) so students get formative feedback, not just professors.
- **Add a transcript export** (PDF or plain text) from the report detail view so TAs can keep evidence outside the app.
- **Render code blocks with syntax highlighting** in `StudentSessionChat.tsx` — students will paste code, and a monospace `<pre>` with even basic Shiki/Prism highlighting would dramatically improve the chat experience.
- **Show an estimated time / question count** to the student at the start of a session so they know how long to budget.

### New Features
- **Canvas LTI / Gradescope handoff.** This is where UW-community impact gets real. Even a one-way export ("download CSV of final scores keyed by UW NetID") would let a TA actually use Ora in a real class.
- **Per-cohort dashboard for the professor:** aggregate suggested vs. final-score divergence, which questions tend to expose weak understanding, average session duration. This turns Ora from a per-student tool into a course-analytics tool.
- **Flag suspected AI-generated submissions.** Given the explicit framing ("AI coding tools widely available"), the natural extension is a heuristic that compares the student's verbal reasoning in the transcript against the structure of their code and surfaces mismatches for the TA to investigate.
- **Plagiarism-style peer-similarity check across sessions** — if two students give near-identical narrations of the same code, flag for review.

### AI Integration Enhancements
- **Adaptive questioning depth.** Have the interviewer use a lightweight scoring pass after every 2-3 turns to decide whether to dig deeper on a weak area or move on. Right now the model just picks the next question on its own with no explicit difficulty signal.
- **Per-criterion rubric anchoring.** Instead of free-text criteria in the report, let the professor define rubric criteria as discrete rows in a new `rubric_criteria` table, and have the model fill in score-per-criterion against that schema. This makes suggested scores comparable across students.
- **Calibration loop.** Once you have ~20 sessions a TA has graded, fine-tune (or few-shot) the report generator against the professor's actual final scores. This turns Ora into a genuinely course-aware grader rather than a generic Claude call.
- **Cite-the-code requirement.** Force the model to quote the specific lines of the student's submission it is asking about. This prevents generic questions and gives the TA reviewable evidence for each rubric judgment.
